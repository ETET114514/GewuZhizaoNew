## 最新：墙体 → 门窗 → 实墙整理

一次识别依次运行三个阶段：

1. `detect_walls` 粗提取墙体，保留为 `coarse_walls`。
2. `detect_openings` 结合墙端、窗框线与门扇开启弧识别门窗。
3. `initialize_refinement` 对齐墙轴与门窗边界，连接洞口两端，用图像支撑保留短墙；`refresh_refinement` 从墙体几何中扣除洞口，生成实墙片段。

不会擦除底图上的门扇、开启弧或整块门窗包围框；只对同方向、相近墙轴上的洞口区间做几何扣除，不切掉垂直相交的墙。相邻墙和玻璃转角提供连接位置，新增实墙部分需有连续深灰像素支撑。

原图结果在 `output/pipeline-v1/`：**26 段粗墙、10 处洞口约束、29 段实墙**。补出了 3、5、10 像素长的三段边缘短墙。`walls` 中共 36 条可编辑轮廓，其中有 10 条洞口连接；这个数字不是 36 段实墙。候选本身仍可能漏检或误分，未检测到的门窗不会自动得到洞口保护。

- `pipeline-comparison.png`：粗识别与整理后的对比。
- `walls.json`：schema 0.3.0，包含原始候选、门窗、可编辑轮廓、洞口提示和派生实墙几何。
- `solid-walls.json`：只导出已扣除洞口的 `solid_wall_segments`，供后续实体建模读取。
- `recognition-overlay.png`：墙体及门窗编号叠加图。
- `page-desktop.png` / `page-mobile.png`：页面实测截图。

页面直接绘制每条轮廓的 `solid_parts`，与 `solid_wall_segments` 一致。延长、缩短、移动、改厚度、补墙之后都会重新应用固定于底图的洞口约束；标为误报后取消对应约束，自动生成的连接随之移除。用户主动编辑的墙轮廓保留。类别待定仍保留洞口，防止把未定类门窗封实；删除自动连接也不会在后续修改时悄悄重新生成。

每次修改/门窗校核的撤销同时恢复轮廓、洞口及实墙数据。保存项目会额外输出 `solid-walls.json`。读取 `walls` 时不能直接填满 `bbox_px`，应读取 `solid_parts` 或扣除 `opening_hints`。历史人工门窗提示也参与区间合并；图幅仍未校准实际尺寸。

## 本地页面：识别 → 直接修改 → 保存项目

3. 指定方向、连接目标或像素调整量，点击「应用修改」。页面程序立即修改几何并更新图形，不需要助手转交处理。
4. 漏掉的墙可框选后应用；程序按矩形长边生成中心线、短边生成厚度，之后仍可调整。
5. 「撤销上一步」最多恢复最近 50 次修改；「保存项目」将当前底图、修改后的 `walls.json` 和 `changes.json` 保存到 `projects/日期时间-编号/`。

例子：选择 W005，选「墙段太短」、向右、连接到 W004；点击应用会将右端直接延长至 W004。选择 W008，填写「向下一直到 W013」，程序识别方向与目标后补竖向转角。转角默认从末端（右/下）开始，可以改选起端（左/上）。

这是本地确定性几何修改器：支持明确的类型、方向、像素量、垂直墙交点，以及少量中文关键词。不是任意自然语言模型。缺参数、方向错误、无法相交、越出图像时会明确报错并保留原图。长度单位是像素；当前延长轮廓不会自动判断新增部分是否属于门窗洞口，这部分留待后续实现。

本轮未实现项目重新导入；已保存的项目文件可供后续功能继续使用。重新识别会开始新一轮，需先保存已有修改。内存结果重启后清空，磁盘项目保留。上传支持 PNG/JPG/WebP，最多 12 MB、400 万像素；服务只监听本机回环地址。

验证覆盖：识别与已有程序一致；修改接口实际更新坐标；保存后的坐标与页面结果配套；撤销恢复原几何；中文方向/目标解析；补墙、删除及错误操作不污染原数据。前端完成语法检查，本轮未做浏览器点击或视觉 QA。可选 WebMCP 工具依浏览器能力启用，尚无已连接上下文验证；手动页面流程不依赖它。

## 已知效果与限制

目视检查可见：左侧长外墙、上方横墙、中部卫生间隔墙、下方卧室的部分竖墙已被提取；床框误识别比初次参数减少。

仍存在漏识别和误识别：中间部分横墙、阳台浅色边界不完整；柜体和洁具周围的边框可能被当作墙。候选在厚度变化、交接点和门洞边缘的位置也可能不准，需要逐段校核。

当前算法按灰度、颜色差和连续线条筛选，支持近似水平、垂直的深灰墙线。它没有学习建筑语义，也没有使用人工标注数据计算准确率；不适用于任意风格、斜墙或透视照片。图像分辨率变化后需要调整像素参数。

所有尺寸单位均为**像素**。图中没有已知尺寸，因此 `scale_mm_per_px` 为 `null`。本结果不能用于施工尺寸。

## 运行

需要 Python 3.10 及以上。首次安装依赖：

```powershell
python -m pip install -r requirements.txt
```

在本目录运行：

```powershell
python recognize_walls.py input/floorplan.png --output output
```

识别另一张图片：

```powershell
python recognize_walls.py "你的户型图.png" --output another-result
```

同一输出目录中的 `walls.json` 和 `walls-overlay.png` 会被覆盖；要保留旧结果，请换一个输出目录。

调整参数示例：

```powershell
python recognize_walls.py input/floorplan.png --output experiment --threshold 170 --min-thickness 6
```

亮度阈值越高，浅灰区域越容易进入候选；最小厚度越大，细边框越容易排除，也越容易漏掉薄墙。`--help` 可查看全部参数。

## 坐标约定

原点在图片左上角，x 向右，y 向下。`start_px` / `end_px` 是候选中心线的两端，`thickness_px` 是候选宽度。这三者是编辑器的主要几何数据；`bbox_px`、`length_px`、`orientation` 是派生值，程序在修改几何后重新计算，并更新页面图形。

自动候选的 `review_status` 为 `unreviewed`；页面直接修改后的墙段标记为 `edited`。文件同时记录输入图片哈希及算法参数，便于后续重复比较。
